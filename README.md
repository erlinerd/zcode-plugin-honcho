# Honcho Memory for ZCode

A small, fail-open ZCode plugin that gives ZCode a shared Honcho memory loop:

- recall a compact peer context at `SessionStart`;
- persist user/assistant turns through a local outbox at `Stop`;
- retry failed uploads on the next session start;
- keep hook failures and network failures from blocking ZCode.

This plugin is intentionally different from the Langfuse observability plugin.
It does not upload every tool input/output by default and does not read hidden
chain-of-thought.

> Status: early community plugin (`0.1.1`). The MVP is designed for personal
> use first. Review the privacy settings before enabling remote memory.

## Configuration

Configure the plugin's `userConfig` values in ZCode, or use environment variables
for local tests and managed installs:

```text
HONCHO_API_KEY
HONCHO_BASE_URL
HONCHO_WORKSPACE_ID
HONCHO_PEER_ID
HONCHO_ASSISTANT_PEER_ID
HONCHO_ENABLED
HONCHO_INJECT_CONTEXT
HONCHO_CAPTURE_PROMPTS
HONCHO_CAPTURE_RESPONSES
HONCHO_MAX_CONTEXT_CHARS
HONCHO_MAX_CAPTURE_CHARS
HONCHO_DEBUG
```

`HONCHO_BASE_URL` defaults to `https://api.honcho.dev`.
`HONCHO_ASSISTANT_PEER_ID` defaults to `zcode`.
The workspace and peer IDs must be stable if memory is shared with another
agent integration.

The API key is only read locally by the hook process. Do not commit it or put
it in `hooks/hooks.json`.

## Privacy defaults

- user prompts and final assistant responses: captured, bounded;
- tool inputs and successful tool outputs: not captured;
- injected context: bounded before it reaches ZCode stdout;
- local outbox/state: stored below `ZCODE_PLUGIN_DATA` with restrictive modes;
- malformed payloads, missing credentials, and Honcho errors: fail open.

## Development

Requirements: Node.js 20+.

```bash
npm ci
npm run check
npm run package:plugin
```

The plugin bundle is generated at
`dist/plugins/zcode-plugin-honcho/hooks/entry.mjs`; `dist/` is the installable
marketplace tree. The tagged release workflow packages it into a versioned ZIP.

## Local smoke test

```bash
printf '%s\n' '{"hook_event_name":"SessionStart","session_id":"smoke"}' \\
  | HONCHO_DEBUG=true \\
    node dist/plugins/zcode-plugin-honcho/hooks/entry.mjs
```

A healthy hook emits either `{}` or a protocol object containing bounded
`hookSpecificOutput.additionalContext`; diagnostics go to stderr.

## Local installation for testing

ZCode treats a selected directory as a **plugin marketplace**, so this
repository includes `marketplace.json` at its root. Build first, then use
**Settings → Plugins → Add marketplace → Select directory** and choose this
repository. Install `zcode-plugin-honcho` from the resulting personal marketplace,
enable it, and configure its `userConfig` values.

The plugin manifest is at `.zcode-plugin/plugin.json`; the hook declaration is
at `hooks/hooks.json`.

## Install a release

Download `zcode-plugin-honcho-v<version>.zip` from the release page, extract
it, and add the extracted directory as a local marketplace via **Settings →
Plugins → Add marketplace**. The ZIP is itself a marketplace shell: its
`marketplace.json` resolves `zcode-plugin-honcho` from the bundled `plugins/`
directory, so no build step is needed on the installing machine. Do not add a
fresh checkout of this repository as a marketplace: it has no `dist/` bundle
(generated, not committed), so hooks cannot start. For a development install
from a checkout, run `npm install` first — the `prepare` hook builds `dist/`.

- Marketplace manifest: <https://raw.githubusercontent.com/erlinerd/zcode-plugin-honcho/main/marketplace.json>
- Plugin manifest: <https://raw.githubusercontent.com/erlinerd/zcode-plugin-honcho/main/.zcode-plugin/plugin.json>
- Latest release (asset: `zcode-plugin-honcho-v<version>.zip`): <https://github.com/erlinerd/zcode-plugin-honcho/releases/latest>
- Official ZCode plugin documentation: <https://zcode.z.ai/en/docs/plugin>
- Official ZCode plugin marketplace: <https://github.com/zai-org/zcode-plugins>

The repository marketplace is named `zcode-plugin-honcho`, and its
`marketplace.json` resolves the plugin from
`source: "./dist/plugins/zcode-plugin-honcho"`. Versioned release
assets are generated by the tagged GitHub Actions workflow.

After installing, set `honcho_api_key`, `honcho_workspace_id`, and
`honcho_peer_id` in the plugin settings. Without them the plugin stays silent
by design: hooks emit `{}` and no memory is read or written.
